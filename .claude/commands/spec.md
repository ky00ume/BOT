# /spec — Specification-Driven Development

## Purpose
Create a comprehensive specification document before implementing features. This ensures clarity, prevents scope creep, and aligns stakeholders.

## Workflow

1. **Gather Requirements** — Ask clarifying questions about:
   - What you're building and who will use it
   - Essential features and success criteria
   - Technology choices and constraints
   - Project boundaries and guidelines

2. **Create SPEC.md** — Document six key areas:
   - **Objective** — Problem statement and goals
   - **Commands** — Available operations and workflows
   - **Project Structure** — File organization and components
   - **Code Style** — Language conventions and patterns
   - **Testing Strategy** — Unit, integration, E2E approaches
   - **Boundaries** — What's in scope and explicitly out of scope

3. **Surface Assumptions** — Identify unknowns and risks before development

4. **Get Approval** — Request stakeholder sign-off before proceeding
