# Frontend UI Engineering

This document provides comprehensive standards for building production-quality user interfaces.

## Core Principles

The guide emphasizes creating UIs that "look like it was built by a design-aware engineer at a top company — not like it was generated by an AI." This means avoiding common AI aesthetic patterns like excessive gradients, uniform rounding, and generic layouts.

## Architecture Recommendations

Components should be organized with colocation, follow composition-over-configuration patterns, and separate data fetching from presentation. The state management approach should match complexity: local state for UI specifics, context for shared read-heavy values, and server state management for remote data.

## Design System Adherence

Avoid the recognizable "AI look" by adhering strictly to your project's actual design system. Use consistent spacing scales (not arbitrary pixel values), respect typography hierarchies, and employ semantic color tokens rather than raw hex values.

## Accessibility Requirements

Every component must meet WCAG 2.1 AA standards, including keyboard navigation, proper ARIA labels, focus management, and meaningful empty/error states. The guide positions accessibility as "a legal requirement in many jurisdictions and an engineering quality standard."

## Quality Verification

Before shipping, components should be tested for keyboard accessibility, screen reader compatibility, responsive behavior across breakpoints (320px–1440px), and proper handling of loading/error/empty states.

The document includes a verification checklist and identifies common red flags like oversized components, inline styles, and missing state handling.
