# Idea Refine

This skill guides you through **structured ideation** in three phases:

## The Process

**Phase 1 (Divergent):** Understand the raw idea by restating it as a "How Might We" question, asking sharpening questions about users and success, then generating 5-8 variations using different lenses (inversion, simplification, audience shifts, etc.).

**Phase 2 (Convergent):** Cluster resonant ideas into 2-3 directions, stress-test them against user value/feasibility/differentiation, and surface hidden assumptions and risks.

**Phase 3 (Ship):** Produce a markdown one-pager with problem statement, recommended direction, key assumptions to validate, MVP scope, and—critically—a "Not Doing" list that makes trade-offs explicit.

## Core Philosophy

As the instructions note, "Simplicity is the ultimate sophistication." The approach prioritizes user experience, saying no to complexity, and challenging assumptions rather than defaulting to convention.

## Invocation

Trigger phrases include "Help me refine this idea," "Ideate on [concept]," or "Stress-test my plan."

## Key Red Flags to Avoid

- Generating shallow variations instead of considered ones
- Skipping the "who is this for" question
- Proceeding without surfacing assumptions
- Being a "yes-machine" rather than pushing back critically
- Omitting the "Not Doing" list

The output is a concrete artifact saved to `docs/ideas/` only after user confirmation.
